# Mailer

Infrastructure adapter for transactional emails.

The application-facing port lives in
`src/modules/identity-access/domain/ports/mailer.port.ts`. This adapter only
implements that contract; use cases should not import from `infrastructure`.

Current provider:

- Hostinger SMTP over implicit TLS on port `465` using Nodemailer.

Template renderer:

- Nunjucks.
- Templates live in `src/infrastructure/mailer/templates/<template-name>`.
- Every template has `html.njk` and `text.njk`.

Current template flows:

- `seller-invitation`: admin creates a seller account and invites the seller.
- `seller-access-code`: seller receives a one-time access code.
- `account-confirmation`: reserved template for a future user confirmation flow.
- `password-recovery-code`: sends the one-time Supabase recovery OTP through
  MailerSend without exposing it in the action URL.

Action links are generated by the infrastructure adapter. Seller invitation
links contain only a cryptographically random, 256-bit opaque token. The API
stores its SHA-256 digest, never the raw token, and consumes the invitation only
after the seller submits a valid password. The URL therefore exposes neither
the email address nor the six-digit fallback code.

- `SELLER_ACTIVATION_URL`: seller activation form URL.
- `ACCOUNT_CONFIRMATION_URL`: future general account confirmation form URL.
- `PASSWORD_RESET_URL`: password reset form URL; only the normalized email is
  preloaded and the user must type the one-time code received by email.
- `APP_WEB_URL`: fallback origin used when either action URL is omitted.

The web application must submit either `actionToken + password` (button flow) or
`email + accessCode + password` (manual fallback) to the confirmation endpoint.
Opening an email link never consumes the credential by itself. Both credentials
share the same expiration and one-use invitation record; resending revokes the
old link and code.

The SMTP username and password must stay in ignored env files as
`MAILERSEND_SMTP_USER` and `MAILERSEND_SMTP_PASSWORD`. Never commit real
credentials. The `MAILERSEND_*` prefix is retained for deployment compatibility,
but the configured relay is Hostinger. Authenticate with the primary mailbox;
aliases can be used as the sender and reply-to addresses.
